Bối Cảnh Dự Án & Mục Tiêu Nghiệp Vụ

Bài toán tuyển dụng yêu cầu xây dựng ứng dụng Web "PKS Course & Enrollment Portal" phục vụ tra cứu, quản lý và ghi danh các khóa học công nghệ thực chiến của PKS Education. Hệ thống có 2 phân hệ người dùng độc lập: Học viên (Student) và Quản trị viên (Admin).

Các thách thức kỹ thuật cốt lõi được giải quyết trong dự án bao gồm:

  • Xử lý Concurrency & Race Condition: Bảo đảm khi nhiều học viên cùng tranh nhau suất cuối cùng của một khóa học, hệ thống xử lý nguyên tử ở tầng CSDL và tuyệt đối không bao giờ xảy ra Overbooking (số lượng đăng ký vượt quá sĩ số tối đa).
  • Bảo vệ Bất biến Sĩ số của Quản trị viên: Ngăn chặn Admin vô tình hoặc cố ý hạ sĩ số tối đa của khóa học xuống thấp hơn số lượng học viên đã đăng ký thực tế bằng cơ chế Row Locking độc quyền.
  • Phân quyền RBAC nghiêm ngặt & Chống IDOR: Học viên chỉ xem và hủy được khóa học của chính mình, chặn đứng mọi hành vi truy cập trái phép vào API quản trị qua JWT Role Guard.
  • Trải nghiệm Giao diện Cao cấp (Dual Theme & Mobile First): Hỗ trợ song song Chế độ Sáng / Tối, vùng chạm tối thiểu 44px chuẩn Apple HIG, thẻ Course Card đủ 8 thông tin bắt buộc với định dạng tiền tệ không bao giờ rớt dòng.

import express, { Application, Request, Response } from 'express';
import cors from 'cors';
import { apiRouter } from './routes/index.js';
import { errorHandler } from './middlewares/error.middleware.js';

export const createApp = (): Application => {
  const app = express();

  // 1. CORS Configuration cho phép Vercel Client & Localhost
  const allowedClient = process.env.CLIENT_URL;
  app.use(cors({
    origin: (origin, callback) => {
      if (!origin) return callback(null, true);
      if (
        !allowedClient ||
        allowedClient === '*' ||
        origin === allowedClient ||
        origin.endsWith('.vercel.app') ||
        origin.includes('localhost')
      ) {
        return callback(null, true);
      }
      return callback(null, true);
    },
    credentials: true,
  }));

  // 2. Body Parser Middlewares
  app.use(express.json());
  app.use(express.urlencoded({ extended: true }));

  // 3. Healthcheck Endpoint đồng bộ Múi giờ Asia/Ho_Chi_Minh
  app.get(['/', '/health', '/api/health'], (_req: Request, res: Response) => {
    res.json({
      status: 'ok',
      service: 'PKS Course & Enrollment Portal API',
      timestamp: new Date().toISOString(),
      timezone: 'Asia/Ho_Chi_Minh',
    });
  });

  // 4. RESTful API Routes (/api/auth, /api/courses, /api/student, /api/admin)
  app.use('/api', apiRouter);

  // 5. Global Error Handler Middleware
  app.use(errorHandler);

  return app;
};

3. Sơ Đồ Quan Hệ Thực Thể Chi Tiết (Entity Relationship Diagram - ERD)

Chuẩn hóa 3NF với 3 thực thể users, courses, enrollments, ràng buộc toàn vẹn khóa ngoại onDelete: Restrict và compound unique (user_id, course_id).

Giải Thích Thiết Kế CSDL & Ràng Buộc Toàn Vẹn

Mô hình dữ liệu được thiết kế tối ưu theo chuẩn Dạng chuẩn 3 (3NF) nhằm loại bỏ dư thừa dữ liệu và bảo đảm tính bất biến:

  • Ràng buộc duy nhất @@unique([user_id, course_id]): Khóa phức hợp này ngăn chặn việc 1 học viên ghi danh 2 lần cho cùng 1 khóa học ngay từ tầng CSDL, kể cả khi có 2 request song song vượt qua tầng validation code.
  • Khóa ngoại Restrict onDelete: Restrict: Ngăn chặn việc Admin vô tình xóa một khóa học hoặc một người dùng khi họ đã có dữ liệu ghi danh. Điều này bảo vệ toàn vẹn lịch sử giao dịch và dữ liệu đối soát kế toán.
  • Chỉ mục hiệu năng (Indexing): Đánh chỉ mục B-Tree trên các trường hay tìm kiếm và lọc: email, category và is_active, giúp tốc độ phản hồi đạt $O(\log N)$ ngay cả khi dữ liệu tăng lớn.

4. Sơ Đồ Phân Quyền & Luồng Người Dùng (RBAC & Use Case Flow)

Phân định ranh giới nghiệp vụ giữa Học viên (Student) và Quản trị viên (Admin/Staff) thông qua JWT claims và Protected Routes.

Giải Thích Cơ Chế Bảo Mật 2 Lớp (RBAC & Anti-IDOR)

Hệ thống bảo vệ tài nguyên thông qua quy chuẩn phân quyền 2 lớp độc lập:

  • Tầng 1 (Authentication Guard): authenticateJWT kiểm tra Header Authorization: Bearer <token>, giải mã JWT và gán thông tin vào req.user. Nếu token giả mạo hoặc hết hạn → trả ngay HTTP 401 Unauthorized.
  • Tầng 2 (RBAC Role Guard): requireRole('admin') kiểm tra thuộc tính req.user.role. Nếu người dùng chỉ mang role student nhưng cố tình gọi các endpoint /api/admin/* → trả ngay HTTP 403 Forbidden và ghi log an ninh.
  • Phòng chống IDOR (Insecure Direct Object References): Tại API xem khóa học đã đăng ký hoặc hủy khóa học, Backend không lấy user_id từ Client gửi lên mà chỉ trích xuất từ req.user.id của JWT đã xác thực. Do đó, học viên hoàn toàn không thể xem hoặc hủy hộ khóa học của học viên khác.

server/src/middlewares/role.middleware.ts 
import { Request, Response, NextFunction } from 'express';
import { sendError } from '../utils/apiResponse.js';

export const requireRole = (role: 'student' | 'admin') => {
  return (req: Request, res: Response, next: NextFunction): void => {
    if (!req.user) {
      sendError(res, 'UNAUTHORIZED', 'Chưa xác thực người dùng.', 401);
      return;
    }

    // Chặn đứng Student cố tình gọi API Admin với mã 403 Forbidden
    if (req.user.role !== role) {
      sendError(
        res,
        'FORBIDDEN',
        'Truy cập bị từ chối: Bạn không có quyền truy cập chức năng này.',
        403
      );
      return;
    }

    next();
  };
};

5. Sơ Đồ Tuần Tự Xử Lý Race Condition & Concurrency Tranh Suất Cuối

Mô phỏng trường hợp 2 học viên bấm ghi danh tại cùng một mili-giây khi khóa học chỉ còn lại duy nhất 1 suất (capacity = 20, enrolled_count = 19).

Giải Thích Bản Chất Race Condition & Kỹ Thuật Atomic Update

Trong các hệ thống đặt chỗ thông thường, lập trình viên thường viết mã theo trình tự: (1) Đọc số lượng học viên findUnique(), (2) Kiểm tra if (count < capacity), (3) Tăng số lượng update(count + 1). Đây là lỗi kinh điển Time-of-Check to Time-of-Use (TOCTOU). Khi có 2 request gửi đến cùng một mili-giây, cả hai cùng đọc được số lượng 19 < 20 và cùng thực hiện tăng lên 20, dẫn đến khóa học có 21 học viên (Overbooking).

Giải pháp của PKS Portal:

  • Sử dụng lệnh Atomic Conditional Update trực tiếp tại tầng CSDL PostgreSQL bên trong prisma.$transaction: UPDATE "courses" SET "enrolled_count" = "enrolled_count" + 1 WHERE "id" = :id AND "enrolled_count" < "capacity"
  • PostgreSQL sử dụng cơ chế Row-level Lock nội tại khi chạy lệnh UPDATE. Request của Học viên A đến trước cập nhật thành công (Affected Rows = 1).
  • Ngay sau khi lock giải phóng, request của Học viên B được đánh giá. Lúc này enrolled_count đã là 20, điều kiện 20 < 20 trả về FALSE → Affected Rows = 0.
  • Service phát hiện số dòng bị ảnh hưởng bằng 0, ngay lập tức ném lỗi COURSE_FULL và Rollback Transaction. Bảo toàn sĩ số 100% không bao giờ vượt quá capacity.

server/src/services/enrollment.service.ts Mã Nguồn Xử Lý Nguyên Tử 
export class EnrollmentService {
  static async enrollCourse(userId: string, courseId: string) {
    const trimmedCourseId = courseId.trim();

    return await prisma.$transaction(async (tx) => {
      // 1. Kiểm tra khóa học tồn tại & đang mở ghi danh
      const targetCourse = await tx.course.findUnique({
        where: { id: trimmedCourseId },
      });

      if (!targetCourse) {
        throw new AppError('COURSE_NOT_FOUND', 'Không tìm thấy khóa học.', 404);
      }
      if (!targetCourse.is_active) {
        throw new AppError('COURSE_INACTIVE', 'Khóa học hiện không mở đăng ký.', 400);
      }

      // 2. Chặn ghi danh trùng lặp (nếu đã có bản ghi chưa bị hủy)
      const existingEnrollment = await tx.enrollment.findUnique({
        where: {
          user_id_course_id: { user_id: userId, course_id: trimmedCourseId },
        },
      });
      if (existingEnrollment && existingEnrollment.status !== 'cancelled') {
        throw new AppError('ALREADY_ENROLLED', 'Bạn đã ghi danh khóa học này rồi.', 409);
      }

      // 3. Kiểm tra sĩ số trước khi cập nhật
      if (targetCourse.enrolled_count >= targetCourse.capacity) {
        throw new AppError('COURSE_FULL', 'Khóa học đã đủ sĩ số tối đa.', 400);
      }

      // 4. POSTGRESQL ATOMIC CONDITIONAL UPDATE CHỐNG RACE CONDITION
      // Lệnh thực thi nguyên tử ở tầng CSDL: Chỉ tăng count nếu enrolled_count < capacity
      const updateResult = await tx.$executeRaw`
        UPDATE "courses"
        SET "enrolled_count" = "enrolled_count" + 1, "updated_at" = NOW()
        WHERE "id" = ${trimmedCourseId} AND "enrolled_count" < "capacity" AND "is_active" = true
      `;

      // Nếu 0 dòng bị ảnh hưởng (khóa học đã đầy do tiến trình khác vừa chiếm suất cuối)
      if (updateResult === 0) {
        throw new AppError('COURSE_FULL', 'Khóa học đã đủ sĩ số tối đa.', 400);
      }

      // 5. Tạo mới hoặc tái kích hoạt bản ghi enrollment
      let enrollment;
      if (existingEnrollment && existingEnrollment.status === 'cancelled') {
        enrollment = await tx.enrollment.update({
          where: { id: existingEnrollment.id },
          data: { status: 'enrolled', updated_at: new Date() },
          include: { course: true },
        });
      } else {
        enrollment = await tx.enrollment.create({
          data: { user_id: userId, course_id: trimmedCourseId, status: 'enrolled' },
          include: { course: true },
        });
      }

      return {
        ...enrollment,
        registration_date: formatDateVN(enrollment.created_at),
      };
    });
  }
}

6. Sơ Đồ Khóa Dòng Quản Trị & Bảo Vệ Bất Biến Sĩ Số (Capacity Invariant)

Cơ chế Row Locking SELECT ... FOR UPDATE đảm bảo Quản trị viên không bao giờ có thể hạ sĩ số tối đa xuống thấp hơn số học viên đã ghi danh thực tế.

Giải Thích Cơ Chế Khóa Dòng Độc Quyền (Pessimistic Locking)

Đề bài đặt ra yêu cầu bất biến nghiêm ngặt: "Sĩ số tối đa (capacity) không được thiết lập thấp hơn số lượng học viên đã ghi danh thực tế (capacity ≥ enrolled_count)".

Nếu chỉ đọc dữ liệu thông thường, trong lúc Admin đang mở form sửa sĩ số từ 25 xuống 15, có thể có học viên thứ 16, 17, 18 vừa đăng ký thành công. Nếu không có cơ chế khóa, hệ thống sẽ ghi đè giá trị 15 vào CSDL, tạo ra trạng thái vô lý (đã có 18 người trong lớp nhưng sĩ số tối đa chỉ là 15).

Cách triển khai tại AdminService:

  • Thực thi lệnh SELECT * FROM "courses" WHERE "id" = :id FOR UPDATE để khóa độc quyền dòng dữ liệu của khóa học này.
  • Mọi request ghi danh từ học viên khác tác động vào khóa học này trong cùng thời điểm sẽ phải chờ cho đến khi transaction của Admin hoàn tất.
  • Kiểm tra điều kiện: Nếu new_capacity < current.enrolled_count → Lập tức Rollback và trả về HTTP 400 Bad Request thông báo lỗi chi tiết.

export class AdminService {
  static async updateCourse(id: string, data: UpdateCourseDTO) {
    return await prisma.$transaction(async (tx) => {
      // 1. KHÓA DÒNG ĐỘC QUYỀN VỚI SELECT ... FOR UPDATE
      const rows = await tx.$queryRaw<any[]>`
        SELECT * FROM "courses" WHERE "id" = ${id} FOR UPDATE
      `;

      if (!rows || rows.length === 0) {
        throw new AppError('COURSE_NOT_FOUND', 'Không tìm thấy khóa học.', 404);
      }

      const current = rows[0];

      // 2. KIỂM TRA BẤT BIẾN: SĨ SỐ MỚI KHÔNG ĐƯỢC NHỎ HƠN ENROLLED_COUNT THỰC TẾ
      if (data.capacity !== undefined) {
        if (data.capacity <= 0 || data.capacity < current.enrolled_count) {
          throw new AppError(
            'INVALID_CAPACITY',
            `Sĩ số tối đa (${data.capacity}) không hợp lệ hoặc thấp hơn số lượng học viên đã ghi danh thực tế (${current.enrolled_count}).`,
            400
          );
        }
      }

      // 3. Cập nhật khóa học sau khi thỏa mãn bất biến
      const updatedCourse = await tx.course.update({
        where: { id },
        data: {
          title: data.title?.trim(),
          category: data.category?.trim(),
          instructor: data.instructor?.trim(),
          description: data.description?.trim(),
          price: data.price,
          capacity: data.capacity,
          is_active: data.is_active,
        },
      });

      return updatedCourse;
    });
  }
}

7. Sơ Đồ Máy Trạng Thái Vòng Đời Ghi Danh (Enrollment State Machine)

Các trạng thái ghi danh trong CSDL (enrolled, confirmed, cancelled, pending) và quy trình hoàn sĩ số tự động.

Giải Thích Vòng Đời Trạng Thái & Tự Hủy Hoàn Sĩ Số

Bản ghi Enrollment quản lý một máy trạng thái hữu hạn (Finite State Machine):

  • Khởi tạo (enrolled): Khi học viên bấm ghi danh thành công, sĩ số enrolled_count được tăng lên 1 và bản ghi mang trạng thái mặc định enrolled.
  • Duyệt chính thức (confirmed): Quản trị viên duyệt danh sách sau khi học viên hoàn tất nghĩa vụ học phí.
  • Tự hủy ghi danh (cancelled): Học viên có thể tự bấm "Hủy ghi danh" trong trang "Khóa học của tôi". Khi hủy, hệ thống không xóa cứng bản ghi (nhằm giữ lịch sử audit) mà chuyển trạng thái thành cancelled, đồng thời chạy lệnh SQL giảm sĩ số an toàn: SET "enrolled_count" = GREATEST("enrolled_count" - 1, 0). Hàm GREATEST đảm bảo sĩ số không bao giờ bị âm dưới 0.
  • Tái ghi danh: Nếu học viên sau đó đổi ý muốn đăng ký lại khóa học này, hệ thống sẽ tái sử dụng bản ghi cũ, cập nhật trạng thái trở lại enrolled và tăng lại sĩ số nguyên tử.

export async function cancelStudentEnrollment(enrollmentId: string, userId: string) {
  return await prisma.$transaction(async (tx) => {
    const enrollment = await tx.enrollment.findUnique({
      where: { id: enrollmentId },
      include: { course: true },
    });

    if (!enrollment) {
      throw new AppError('NOT_FOUND', 'Không tìm thấy thông tin ghi danh', 404);
    }

    // Kiểm tra quyền sở hữu tránh lỗ hổng IDOR
    if (enrollment.user_id !== userId) {
      throw new AppError('FORBIDDEN', 'Bạn không có quyền hủy khóa học của học viên khác', 403);
    }

    if (enrollment.status === 'cancelled') {
      throw new AppError('ALREADY_CANCELLED', 'Lượt ghi danh này đã được hủy trước đó', 400);
    }

    // 1. Chuyển trạng thái sang cancelled
    const updated = await tx.enrollment.update({
      where: { id: enrollmentId },
      data: { status: 'cancelled' },
      include: { course: true },
    });

    // 2. GIẢM SĨ SỐ NGUYÊN TỬ VỚI CÔNG THỨC GREATEST BẢO VỆ KHÔNG ÂM
    await tx.$executeRaw`
      UPDATE "courses"
      SET "enrolled_count" = GREATEST("enrolled_count" - 1, 0)
      WHERE "id" = ${enrollment.course_id}
    `;

    return {
      ...updated,
      registration_date: formatDateVN(updated.created_at),
    };
  });
}
