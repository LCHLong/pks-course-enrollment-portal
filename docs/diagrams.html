Phân Tách Trách Nhiệm Phân Tầng (Clean Architecture)

Source code backend được cấu trúc nghiêm ngặt theo mô hình Controller - Service - Data Access:

  • Controllers: Tiếp nhận HTTP request, trích xuất DTO và trả HTTP Response chuẩn { success, data, error }.
  • Services: Chứa toàn bộ nghiệp vụ lõi, giao tác database transaction, kiểm tra điều kiện sĩ số.
  • Middlewares: Đảm bảo tính phòng vệ (Helmet bảo vệ headers, CORS, JWT bảo mật, RBAC role guard).

Triển Khai Độc Lập Monorepo CI/CD

Dự án sử dụng cấu hình npm workspaces kết nối trực tiếp với Vercel:

  • Root Workspace: Đồng bộ dependency và scripts chạy kiểm thử xuyên suốt (npm run build, npm test).
  • Vercel Auto-deploy: Mỗi commit push vào main tự động kích hoạt pipeline build và deploy đồng thời cả hai URL Production.

3. Sơ Đồ Quan Hệ Thực Thể Chi Tiết (Entity Relationship Diagram - ERD)

Chuẩn hóa 3NF với 3 thực thể users, courses, enrollments, ràng buộc toàn vẹn khóa ngoại onDelete: Restrict và compound unique (user_id, course_id).

Prisma 3NF Relational Model

1. Ràng Buộc Khóa Ngoại (Restrict)

Thiết lập onDelete: Restrict trên cả user_id và course_id ngăn chặn việc xóa cứng các khóa học hoặc tài khoản đã có lịch sử ghi danh, tránh phá vỡ tính toàn vẹn dữ liệu kế toán và audit trail.

2. Compound Unique Constraint

Chỉ mục duy nhất @@unique([user_id, course_id]) tại tầng CSDL PostgreSQL đảm bảo một học viên không thể ghi danh trùng 2 lần cho cùng một khóa học, kể cả khi có 2 request gửi đồng thời.

3. Hiệu Năng Chỉ Mục (Indexing)

Đánh index trên category và is_active giúp các truy vấn lọc danh mục và tìm kiếm khóa học của học viên đạt tốc độ $O(\log N)$, đáp ứng tải cao khi nhiều người cùng tra cứu.

6. Sơ Đồ Khóa Dòng Quản Trị & Bảo Vệ Bất Biến Sĩ Số (Capacity Invariant)

Cơ chế Row Locking SELECT ... FOR UPDATE đảm bảo Quản trị viên không bao giờ có thể hạ sĩ số tối đa xuống thấp hơn số học viên đã ghi danh thực tế.

Row-Locking SELECT FOR UPDATE Sequence
sequenceDiagram autonumber actor Admin as 👑 Quản Trị Viên (Staff/Admin) participant API as ⚙️ Express Admin Controller participant Service as 💼 Admin Service participant PG as 🗄️ PostgreSQL Database Admin->>API: PUT /api/admin/courses/:id (payload: { capacity: 15 }) API->>Service: updateCourse(id, { capacity: 15 }) Note over Service,PG: Bắt đầu Transaction & Khóa Dòng (Row Locking) Service->>PG: SELECT * FROM "courses" WHERE "id" = :id FOR UPDATE Note over PG: Dòng khóa học bị LOCK độc quyền.
Không tiến trình nào khác được sửa cho đến khi COMMIT. PG-->>Service: Trả về record hiện tại: { capacity: 25, enrolled_count: 18 } Note over Service: KIỂM TRA BẤT BIẾN NGHIỆP VỤ:
Yêu cầu: capacity mới = 15
Thực tế đã ghi danh: enrolled_count = 18
